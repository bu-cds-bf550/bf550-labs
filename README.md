# BF550 · Labs

The notebooks you work through during lab time, with instructors and TAs in the room. Nothing
here is submitted and nothing here is graded.

## Get them once

```bash
git clone https://github.com/bu-cds-bf550/bf550-labs.git
```

Clone it once, at the start of the term, and keep working in that same copy all semester. When we
tell you there is something new:

```bash
git pull
```

Your own edits and experiments stay where you left them, and a fix we push reaches you on your
next pull.

## Run them

Labs use the `bf550` conda environment your first problem set ships — the one you built in
[lab 1](https://bu-cds-bf550.github.io/labs/unit-01-1/). There is no second environment. Open a
notebook in VS Code and pick the `bf550` kernel.

Each lab carries its own self-checks. They report and never grade: `⬜` not attempted, `X` not
passing yet with a hint, `OK` passing. Run a check as often as you like — it only reads your work.

## Break them

These notebooks are for changing. Move a line, predict what happens, run it, find out you were
wrong — that is what a lab is for, and it is the fastest way to learn to read code. Every cell is
editable on purpose. If you wreck one beyond repair, `git checkout <notebook>` gets you the
original back.

## What is here

One notebook per lab, named `unit-NN-M.ipynb` for unit `NN`, session `M`. Lab 1 is not here — it
is a [page on the course site](https://bu-cds-bf550.github.io/labs/unit-01-1/), because it is the
lab where you set up the toolchain and make this clone.

Labs appear as their units open. A lab marked **Under construction** is drafted but not yet
reviewed; it will change before its meeting.

Everything else about the course — schedule, policies, the textbook — is at
[bu-cds-bf550.github.io](https://bu-cds-bf550.github.io).
